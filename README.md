# Rogue Trip: Vacation 2012 (PSX) — partial decompilation

A **partial** C reconstruction of *Rogue Trip: Vacation 2012* (USA,
`SLUS_006.43`), made to recover the game's **PS-Link (link cable)
two-console multiplayer** so that its design and code can be used to add
networked play to OpenTM2, a Twisted Metal 2 PC port. Rogue Trip runs on the same
SingleTrac engine lineage as Twisted Metal 2.

It is not a complete decompilation. Everything that belongs to the link
game is reconstructed and byte-exact; the rest of the game is still retail
bytes. The project is kept so that anyone who wants to continue the
decompilation can build on it.

The link code was the goal and it is complete: the cable driver, the
session and packet layers, the lobby, and every function in the main
executable that reads the link state or link data. The totals cover the
whole executable, including Sony's PsyQ SDK libraries and 60 BIOS call stubs
(also matching); the rest of the game is open for anyone who wants to carry
on.

## Status

- **202 functions reconstructed in C, all byte-exact.** The hybrid build
  (C functions spliced into the retail executable at their addresses)
  reproduces the retail executable exactly (SHA-256 `ec0ce2dc…6043de`).
- **The complete link-cable stack:**
  - PsyQ *libcomb* and the BIOS `sio` device driver (16 functions);
  - the session layer: open, master/slave handshake, checksummed packets,
    timeout, close;
  - the in-race packet layer (one 32-byte packet per player per frame);
  - the lobby protocol (player count, level, car picks, button maps);
  - every function in the main executable that reads link state or the
    link data: race loop, car select, match setup, events for pickups and
    destroyed objects, controller ports, damage authority, HUD differences,
    `main`.
- **Runtime-tested** between two emulated consoles joined by an emulated
  link cable: long races, pause and quit from either side, a pulled cable,
  and 4 players.
- Not reconstructed: most of gameplay, rendering, sound, AI and the shell
  overlay (the front-end menu, which sends the level message).

## Building

```powershell
python build.py                  # compile every unit, link, splice, report
python build.py --exact-only     # only exact units: must reproduce retail
```

Each build writes `work/build-<timestamp>/psx/RT_HYBRID.EXE` and an image
report. Units, their compilers and flags are listed in
`config/semantic/units.json`:

- most game code: PsyQ 4.4 (`CC1PSX`) with maspsx in ASPSX 2.56 mode;
- some modules: the same with `-fvolatile`;
- the PsyQ runtime library (libcomb): the patched GCC 2.7.2 with GNU as.

Each replaced function is checked against the retail bytes and classified
**exact** or **semantic** (behaviour-equivalent, fits the slot; allowed
only where the manifest says so). Currently none are semantic.

## Tools

| Tool | Purpose |
|---|---|
| `tools/compiler_probe.py` | Compile one unit with a chosen compiler and compare each function with retail |
| `tools/diff_func.py VA` | Retail vs build, side by side (`--retail-only` for a listing) |
| `tools/refs.py VA…` | A function's data, `$gp` and `jal` references |
| `tools/callgraph.py VA…` | Callers and callees |
| `tools/psyq_real.py` | Build a unit with the genuine PsyQ toolchain (driver, ASPSX, PSYLINK) |
| `tools/patch_cc1_win.py` | The library compiler patches (1–19) |
| `tools/objdiff_build.py` | objdiff objects and `objdiff.json` |
| `tools/splat.cmd` | splat disassembly and round-trip check (needs a splat checkout, `SPLAT_DIR`) |
| `tools/m2c_reference.py` | m2c draft per function into `reference/m2c/` (needs an m2c checkout) |
| `tools/extract_disc.py` | Extract files from the disc image |

This repository is meant to sit in the `references/` folder of OpenTM2, the
Twisted Metal 2 PC port, next to the TM2 decompilation; by default
`tools/splat.cmd`, `tools/m2c_reference.py` and `tools/tm2_match.py` find
splat, m2c and the TM2 decomp at their places there (`SPLAT_DIR`, `--m2c`
and `--tm2` point them elsewhere).

## Continuing the decompilation

Pick a function (`config/US/funcs.tsv`), write it in a unit under
`src/semantic/` with `__attribute__((section(".text_<VA>")))`, add the unit
to `config/semantic/units.json`, and iterate with
`tools/compiler_probe.py` until it is exact. `reference/m2c/` has an
automatic draft of every function as a starting point, and
`docs/COMPILER.md` collects the techniques that were needed so far.
